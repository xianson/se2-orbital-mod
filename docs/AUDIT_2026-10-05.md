# Scenario audit, 2026-10-05

Five read-only auditors: player lifecycle, frame events, map and HUD, planning, planet transitions. Every finding was traced
in the code. Status: **fixed** (with an offline test, or with an in-game check), **open**, or **won't fix** (with the reason).
Tests: `Tests/PlayerOrbitTests` (offline, in the fast gate); in-game `tools/harness/hud_cases.sh`, `rv_cases.sh`,
`rv_views.sh`, `map_dim.sh`.

## Structural (the causes)
- [fixed] Player state was separate statics, each written in several branches. Now one `PlayerState`, built fresh every tick from its defaults and published whole (`Core/Frames/PlayerState.cs`, `FrameHost._cur/_pub`).
- [fixed] Client code read server entities. The server now publishes a grid snapshot every 5 ticks (`ServerFrames.View`: position, box, static flag, name, mass); the client reads the anchor box, static check, names and positions from it, and the cached aero beta instead of measuring on the server entity. Left: `Contacts` (sensor logic) still reads server grids. (anchor box, static flag, names, mass, aero beta). Planned: a server-published snapshot.

## Player lifecycle
- [fixed] L1: a merge or shift requested while seated was replayed on standing up (thrown 100+ km). Requests are dropped while seated, on a new character and on a new session (`DropPending`).
- [fixed, offline test] L2: membership went stale when the seated ship split off or arrived. Seated, you leave any frame that isn't the seat's (`PlayerOrbit.KeepMembershipSeated`).
- [fixed, offline test] L3: game fast travel or a teleport out of a frame led to a split onto a bogus orbit. More than 60 km from the berth, you leave quietly (`PlayerOrbit.MovedOut`).
- [fixed] L4: joining a frame swallowed a queued stow. No joining while a stow is pending.
- [fixed, offline test] L5: the 300 m reach is measured from a grid's origin, not its hull (needs grid boxes in the server snapshot).
- [fixed] L6: a dead character's requests were replayed on the respawned one. Cleared on a new character.
- [fixed] L7: the player id wasn't kept current while seated, so a seated save lost membership.
- [fixed, in game] Standing up in a ship stowed with you seated left you in no frame (`PlayerOrbit.FrameToJoin`).

## Frame events

- [fixed] F2: merges in warp. The relative velocity isn't scaled by N, and screens are too sparse at high warp.
- [fixed] F3 (= T2): a lone grid stowed (the ship a seated player flies) isn't turned out of the planet's chart.
- [fixed] F4: a docked ship with dampeners on inflates the anchor's delta-v.
- [fixed] F5: a station's frame can lose host priority in a merge.
- [fixed] F6: a second move of a joined group in one tick is dropped.
- [fixed] F7: new grids (debris, a rotor head, a paste) are only framed by the encounter system, which is off when encounters are off.

## Follow-up, 2026-10-06
- [fixed] T7 landing drift: a teleport moving with something (an arrival at up to the speed cap) is aimed where it will be when it lands, using the measured landing delay.
- [fixed] Contacts: the client reads ownership, encounter flags and sensor blocks from the server's snapshot (`ServerFrames.View` / `SensorViews`), not from the server's entities.
- [fixed] "The player" on the client is the local player's own character (the player controller's possession stack), not the first live character (which could be anyone's on a listen server).
- [fixed] Another world loaded in the same process: when none of the planets the system was built from is left, the system is rebuilt, along with its sites, the frames' server state and the belt rocks.
- [fixed, in game S2] A ship moved far out of its berth (the game's fast travel) leaves its frame quietly, the anchor as well as members, with no split onto a bogus orbit.
- [fixed, found by S5] A seated player read as "in no frame" for a moment after their ship was moved (its client copy lags a big move), which dropped warp to x1 and made the HUD flicker. The last matched grid id is kept for 3 s, using the server's position.
- [fixed, found by S5] Warp was held at x10 by ships nowhere near you: the world's own ships merged into one frame, drifting in it. In a frame you are not in, a member too fast to carry in warp is placed on its own orbit instead of pushed there.
- [fixed] Map statics across a world reload (globes, star model), text-draw failures backed off, icons recovered after a failure.
- [fixed, found by reentry_e2e] A ship's joined sub-grids were moved twice at an arrival (6,700 km off): `GridMembers.Position` reads a queued move, so each member loop added the shift again to grids that had already gone with their ship. Each member loop (arrival, merge, re-pin, slot move) now skips grids moved with an earlier member's joined set; a second operation in the same tick still adds to the queued move.
- [fixed] Rocks capturing frames: the game's encounters spawned (with their rocks) round any grid in the berth lattice; any rock within 8 km became the frame's anchor and re-centred its orbit, then the "dirty slot" move put it in a fresh slot, and the cycle began again (a slot leaked each time).
  - Rocks being deleted that pass are no longer offered as anchors.
  - A rock anchors a frame only if it persists (placed, the mod's, player-edited) or one of the frame's grids is within 2 km of it (asteroid bases and mining next to your ship are unchanged).
  - The slot move is only for persistent rocks; an encounter in the frame itself counts as "its rock".
- [fixed] Encounters no longer spawn round frames nobody is in (the world's own ships, parked in a fresh berth by a split): a spawn-prevention zone over their 20 km bubble, put up at the split itself (the game spawned in the very next tick). Frames you are in, and sites, are unchanged.
- [fixed, found by S5] A merge in warp lost the ship's speed: in physics a member moves N x its true relative velocity, and the game caps physical speed near 1000 m/s (8.5 m/s at x1000 asked 8,500 m/s and got ~980). The merged ship's true velocity is now kept for the warp steering, as every member's is, and the limiter drops warp for it.
- [fixed, found by S5] Stale warp state on an anchor: a grid that had been a member kept its warp scale (x1) after it became an anchor; merged later at x1000, its velocity was multiplied by 1000 again. Anchors now hold no member warp state, and merged grids are recorded at the merge's scale.
- Verified in game: scenarios 11/11 (S5: merged at x1000, 118 m from its own orbit after the warp changes and a later split), reentry_e2e 23/23, no rock captures.
- [fixed, test] reentry_e2e judged frames under the crossing's black (the fade hides the settle on purpose), and read a frame stall as the planet's stand-in giving way (86 deg "jump").
- Known, the game's: a grid moved 6,000 km to a new berth costs a ~230 ms stall in the game's own systems (the mod's split and tick are under 30 ms), at every split and stow.
- Verified in game: reentry_e2e handover 0.0 m / 0.00 m/s off; the fade under warp announced 0.39 s ahead, then out, black, moved, steady, in.
- [feature, 2026-10-06] Holding station (dampeners on; the relative pull skipped):
  - no orbit display while holding (no force: no orbit of your own);
  - charged: each thruster on the face against the pull asks its full rate x the fraction of that face's thrust the pull needs (x warp), through its own resource sink - `StationKeepCharge`; thrusters that push nothing where they are (atmospheric in vacuum) ask nothing; on foot, the suit pays the jetpack's precision-over-stationary rate x the fraction;
  - the pull (so the cost) comes from the orbit: about 3 n^2 per metre radial, n^2 out of plane, ~0 along track, n^2 = mu / r^3;
  - a "Frame origin" marker while riding: where holding is free;
  - verified in game: `tools/harness/holdcharge.sh` 6/6 (creative world: the game itself refuses the suit's drain and drains no stores; the thrusters' asks reach the network).
- [fixed, found by S5] An encounter's static grid (a wreck) that spawned beside your frame became its anchor, re-centred your orbit on itself and split your own ship off. It anchors a frame of yours now only with a reason, as a rock: one of your grids or you within 2 km of it. Your own stations and encounter sites are unchanged.
- [fixed, found by airless.sh] On foot, riding a frame into a planet's frame (moved as far, through the engine's stall), there was no arrival notice and no fade: both now, the move seen from your own place.
- [fixed] The airless clamp logged a 0 % "jolt" on every tick after it (a hair over the cap after the elements' round trip): 0.5 m/s tolerance.
- [verified in game] `tools/harness/burns.sh` 7/7: an armed burn stops warp, flies, lands on the planned apoapsis (347.8 km / 348); armed late it flies what is left (472.3 / 472); a passed manual node does not hide a later armed one; nodes across a save and load (the save's lines through the load's parser, in memory: nothing saved) come back armed, with their target orbits.
- [verified in game] `tools/harness/airless.sh` 3/3 (campaign world, Palatine): 1575 -> 990 m/s at the border with a 16 % jolt, arrival at the cap, faded. No orbit about Palatine meets its border over the cap (escape there is ~480 m/s): only arrivals from outside are clamped. DEV `flyby <body> <peKm> <vInf>` sets one up.
- Known, the game's (researched): a grid landing far from any physics region makes the engine build a new Havok world (server and client) and block the server tick on procedural sector generation; berth slots are 100+ km apart, so every split and stow pays ~230 ms. Avoiding it would need a different berth layout (slots packed inside a region kept alive by a parked body) - a design change, not made.
- In-game scenario script `tools/harness/scenarios.sh`:
  - S1 anchor destroyed: new anchor, 0.2 m from its orbit (no jump);
  - S2 a ship moved 150 km out leaves quietly;
  - S3 seated through a split: you leave the old frame, and on standing up you are in the ship's frame with no split of your own;
  - S4 a pasted grid is adopted with encounters off;
  - S5 warp into a rendezvous.
- Design notes:
  - merges are decided by frame centres, but riding far from your anchor you split off at 20 km first, so you still merge once near;
  - the Lagrange preview treats a frozen burn as one impulse (small error);
  - a ship with dampeners on station-keeps in its frame (by design), so it does not follow its own orbit there.

## Still open
- Multiplayer as a whole: the server side still has one "player" (FrameHost is single-player by design). Per-player state on the server would be a feature, not a fix.
- A world reload in the same process is handled (rebuilt), but untested: the harness cannot load a second world without restarting the game.
